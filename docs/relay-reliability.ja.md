# リレーの信頼性

[English](./relay-reliability.md) | **日本語**

## タイムアウトと再試行

Node HTTP トランスポートは keep-alive を無効にし、検証済み DNS アドレスへ接続を固定します。レスポンス本文を含む要求全体の期限は45秒、ソケットのアイドル期限は35秒です。DNS 解決にも期限があります。SSE はヘッダー受信後に全体期限を解除し、アイドル期限を維持します。ライブラリでは `RelayClientSecurityOptions` の `requestTimeoutMs` と `socketTimeoutMs` を設定できます。タイムアウトのコードは `ETIMEDOUT` です。成功した DNS 固定と安全性エラーはキャッシュし、一時的な DNS 障害だけを同じ検証条件で再試行します。

ワーカーと発注側のポーリングは、一時的なネットワーク障害と HTTP 429/502/503/504 を再試行します。待機時間は125〜250ミリ秒から倍増し、ランダムな揺らぎを加えて最大15〜30秒になります。試行ごとに機密情報を含まない通知を出し、キャンセルで待機を中断できます。認証・検証・SSRF などの恒久的なエラーは即時に失敗します。HTTP 登録も同じ期限で最大5回試行します。POST が既に受理された可能性があるため、送信自体は自動再試行しません。

## HTTP リースと受領確認

`GET /envelopes?recipient=<did>&lease=true`（`/inbox/<did>` も対応）で30秒の可視性リースを取得します。封筒はキューに残り、既存の容量制限に含まれます。未確認の封筒はリース期限後に再配信されますが、元の10分の TTL は延長しません。Durable Object はリースを永続化し、再起動後も維持します。`lease=true` のない要求、SSE、WebSocket は従来どおり取得時に削除します。peek はリースを取得・延長しません。

永続化または処理後に `DELETE /envelopes/<envelopeId>?recipient=<did>` を、新しい受信者用 RelayAuth トークン（`receive` アクション）で呼び出します。削除時は204、既に存在しない場合は404を返します。HTTP クライアントは両方を成功として扱います。他の受信者のキューは読み取り・削除できません。確認してもリプレイ記録は消えず、署名・順序・時刻・認証 nonce の検証を維持します。

ランタイムの HTTP ポーリングはリースを利用します。外部の `HttpRelayClient.receive` 利用者は `{ lease: true }` で有効化し、処理後に `acknowledgeDelivery` を呼びます。クライアントは取得した封筒を検証してから受信者と封筒 ID で重複を排除します。記録期間は10分、上限は16,384件です。処理済み封筒が再配信されると確認を再試行します。重複排除領域が満杯なら安全のため失敗します。

`--inbox` ワーカーは受理記録に `envelopeId` を追加し、ファイルをディスクへフラッシュしてから提案を確認します。再起動時も記録済み ID によって二重追記・二重実行を防ぎます。ID のない旧記録も読めます。永続化が失敗した提案は確認しません。`--inbox` がない場合はアダプター実行成功後に確認します。セッションイベントは監査処理後、制御受領証は消費時に確認します。確認機能のないトランスポートでは従来の動作を維持します。

`--on-receive` は従来どおり永続化後のベストエフォート通知です。耐久性はフックの完了ではなく inbox が担います。外部副作用の厳密な一度だけの実行や、中断した二者間セッションの自動再開は保証しません。永続化前のクラッシュでは再配信され、永続化後は inbox が復旧元です。この変更による公開リレーの自動デプロイは行いません。
